- [ ] Vora has two implementations competing for one route without a cutover state — Existing Vora remains reachable through its legacy page until its richer case study is ready. — failure: Milestone 1 adds Vora as a draft rich record at `/work/vora`. - [ ] The content model permits published entries with no valid destination — Stable slug, name, category, summary, contribution statement, related slugs, optional detail route. A slug alone does not create a published route. — failure: An Agent Team record is set to `published`, placed in the Work catalog, and assigned no detail route. It is included in the 7/3/4 count, but its required detail link is either missing or generated from the slug and returns 404. The record satisfies the proposed field model even though A1 fails. — fix: Use discriminated record types. A published case-study entry must require a resolvable detail route; drafts and collection-only records may omit it. Add a build-time graph validator covering placements, routes, related slugs, and sitemap inclusion. — reviewers: lens:DESIGN, lens:FEASIBILITY.

- [ ] Fixture provenance is separate from the bytes it attests — One of the five explicitly supported demo kinds, with fixture ID and display copy. — failure: A developer replaces the JSON behind `control-center-default` to correct a sample run but leaves the project record's checked date and About-this-example copy unchanged. The page now presents new bytes under old review metadata, while schema and private-pattern tests still pass. — fix: Model each example as an immutable evidence snapshot that binds fixture revision or digest, derivation, checked date, disclosure, and approved public fields. Make interactions reference that snapshot, and fail validation when fixture bytes change without a new attestation. — reviewers: lens:DESIGN.

- [ ] Enhancement recovery has no failure-independent owner — A failed enhancement retains readable static content and offers retry without exposing dead controls. — failure: The Vora demo's dynamically loaded JavaScript chunk returns 404 after the server-rendered page loads. The enhancement never hydrates, so a retry control implemented inside that enhancement cannot render or respond; showing its normal controls instead exposes dead buttons. — fix: Put static content and recovery in a separately loaded, server-rendered demo shell. Have an outer error boundary own module loading and retry, and provide a native page-reload link that works even when the demo bundle never executes. — reviewers: lens:DESIGN, lens:SCOPE.

- [ ] Optional galleries become a mandatory first-release subsystem — Catalog, case-study sections, evidence labels, responsive media/gallery, static fallback. — failure: None of the five first-release asset inventories contains a gallery, but Milestone 1 and A4 still require gallery implementation and lifecycle verification. Add it only when a flagship has multiple reviewed images that require enlargement. — reviewers: lens:SCOPE.

Copy only manifest-approved assets into the production public tree, fail production builds on unapproved files, and test direct asset URLs plus client bundles using synthetic draft sentinels. — reviewers: lens:SECURITY.

- [ ] The open-image fallback can execute active content on the site's origin — Media failure retains the caption, text walkthrough, and retry/open-image option. — failure: A captured poster is mistakenly stored as `public/work/prism/poster.html` and contains a script. Test that open-image destinations cannot execute script. — reviewers: lens:SECURITY.
